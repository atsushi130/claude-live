# claude-live

日本語の音声で Claude Code を操作するための一式。
議論するだけでなく、調査を頼み、実装を指示し、他のスキルを呼び出すところまで声で行える。
音声認識と音声合成をすべて手元で行うため、**音声データは外部に送信されず、API キーも要らない**。

## 構成

```
.claude-plugin/marketplace.json      配布元の定義（リポジトリのルート）
claude-live/                         プラグイン本体
├── skills/claude-live/
│   ├── SKILL.md                     音声で操作するときの作法
│   ├── scripts/
│   │   ├── claude-live              MCP サーバー本体（単体で動く実行ファイル）
│   │   ├── start-claude-live        Claude Code を起動して音声操作を始める
│   │   ├── ensure-engine            読み上げエンジンが無ければ導入する
│   │   ├── use-engine               読み上げエンジンを切り替える
│   │   ├── end-voice-session        音声の終わりを知らせる（SubagentStop / SessionEnd フック用）
│   │   └── stop-engines             読み上げエンジンを止める（SessionEnd フック用）
│   └── resources/
│       └── dictionary.tsv           読み方の辞書（自由に編集できる）
├── skills/fixing-pronunciation/
│   └── SKILL.md                     読み間違いを辞書で直すときの手順
├── agents/claude-live.md            音声で操作するときの作業を受け持つエージェント
├── .claude-plugin/plugin.json       プラグインの定義
├── .mcp.json                        MCP サーバーの定義
└── hooks/hooks.json                 SessionEnd / SubagentStop のフック

claude-live-pet/                     画面にドット絵を出すプラグイン（任意）
├── skills/add-pet/SKILL.md          自分のペットを登録する
├── skills/select-pet/SKILL.md       表示するペットを選ぶ・見た目を変える
├── scripts/
│   ├── claude-live-pet              オーバーレイ本体（単体で動く実行ファイル）
│   ├── start-pet / stop-pet         claude-live の on-start / on-end から呼ぶ
│   ├── add-pet / select-pet         スキルの中身
│   ├── slice-sheet                  スプライトシートを行ごとに切り出す
│   ├── connect                      claude-live に自分を繋ぐ（SessionStart フック用）
│   └── paths.sh                     配布物と書き込み先の決め方
├── resources/pets/clawd/            同梱のペット（既定）。コマ画像・manifest.json・pet.json
├── .claude-plugin/plugin.json       プラグインの定義
└── hooks/hooks.json                 SessionStart のフック
```

`skills/` `.mcp.json` `hooks/hooks.json` はいずれもプラグインルート直下に置く決まりで、
この位置にあれば自動で見つかる。`plugin.json` に書き足す必要はない。

実行ファイルと辞書はスキルディレクトリの中に置いている。`~/.claude/skills/claude-live`
への symlink 1 本で一式に到達できるので、スキル単体で完結する。

実行ファイルは macOS 同梱の Swift ランタイム（`/usr/lib/swift`）だけに依存するので、
**配布先に Swift の開発環境は要らない**。必要なのは macOS 26 以降
（`SpeechAnalyzer` / `SpeechTranscriber` を使うため）。

`claude-live/skills/claude-live/scripts/claude-live` はビルド済みの実行ファイルで、これ単体で動く。

## 導入する

プラグインとして入れる。

```
/plugin marketplace add <このリポジトリ>
/plugin install claude-live@claude-live
/plugin install claude-live-pet@claude-live   # 任意。画面にドット絵を出す
```

スキルの認識、MCP サーバーの登録、終了時の後片付けはこれで揃う。MCP の
`command` は `${CLAUDE_PLUGIN_ROOT}` から解決されるので、置き場所を書き換える必要はない。
読み上げエンジンの導入も不要で、初回起動時に `ensure-engine` が面倒を見る。

話者や速度を変えるときだけ `use-engine` を使う（下記「切り替える」）。
これは `~/.config/claude-live/config.json` に書くので、プラグインで入れても
手で繋いでも同じように効く。

### 手で繋ぐ場合

プラグインを使わずに動かすなら 3 か所を自分で繋ぐ。

```bash
# 1. スキルを認識させる（スキルごとに 1 本ずつ張る）
ln -sfn "$PWD/claude-live/skills/claude-live" ~/.claude/skills/claude-live
ln -sfn "$PWD/claude-live/skills/fixing-pronunciation" ~/.claude/skills/fixing-pronunciation

# 2. MCP サーバーを登録する（user スコープに書き込む）
claude mcp add-json claude-live \
  "{\"type\":\"stdio\",\"command\":\"$PWD/claude-live/skills/claude-live/scripts/claude-live\",\"args\":[\"mcp\"],\"timeout\":3900000}" \
  --scope user
```

`timeout` は 65 分。ツール側の録音上限（60 分）と stdio の既定（30 分）の
どちらより長くしておかないと、沈黙して待っている間に打ち切られる。

3 つ目は `~/.claude/settings.json` の `SessionEnd` に `stop-engines` を追記すること
（下記「終了時にプロセスを片付ける」）。

## 何をするもの

Claude Code に `converse` / `speak` / `listen` の 3 つのツールを追加する。
Claude が `converse` を繰り返すことで、声での往復が成立する。

| ツール | 動作 |
| --- | --- |
| `converse` | 読み上げてから発話を聞き取り、書き起こしを返す。音声操作の主役 |
| `speak` | 読み上げのみ |
| `listen` | 聞き取りのみ |

発話の始まりは入力レベルで、終わりは無音の継続時間で自動判定するため、
話し終わればキー操作は不要。既定では**無音 3 秒**で確定する
（言葉に詰まっても切られないための余裕）。

判定の閾値は環境ノイズの推定から決まる。推定は開始時に固定するのではなく
**録音中ずっと追従させている**ので、静かな部屋でも空調のある部屋でも、
途中でマイクを切り替えても設定を変えずに使える。特定の部屋に合わせた値は持っていない。

黙っていても打ち切らない。1 回の呼び出しが最大 1 時間ブロックし、その間は
何も言わずに待ち続ける。環境音や読み上げの残響を拾った短い断片（「あー。」など）は
発話として扱わないので、黙っているのに応答されることはない。

**発話が無いまま累計 1 時間が過ぎると、記録を残して終了する。** 1 時間会話が無ければ
席を外している可能性が高く、待ち続けても得るものが乏しいため。それより前に
自分の判断で終わることはしない（下記「トークン消費」を参照）。

## 始まったことを声で知らせる

音声のやり取りが始まると、**まず「ライブセッションを開始します」と読み上げる。**

**モデルの応答に任せず、MCP サーバー側で読み上げている。** 「音声で操作できる状態に
なった」は仕組みの側の事実で、言い忘れや言い換えが起きてはならない。最初のツール呼び出しで
1 回だけ鳴り、同じセッションでも一度終えてから話しかけ直せばまた鳴る。

**エンジンの解決を待ってから鳴らす。** 暖機は `initialize` の時点で走り始めるが、
最初の一言はその直後に来る。解決の途中で「まだ決まっていない」と答えてしまうと
macOS 内蔵音声にすり替わるので、待ち合わせてから読み上げる。どの経路で鳴らしたかは
記録に残る（`~/.local/state/claude-live/hook.log`）。

文言は `~/.config/claude-live/config.json` で変えられる。**空文字を書くと鳴らさない。**

```json
{ "opening": "はい、聞こえています" }
```

## 常駐して使う

必要なときだけ話す使い方（起動しっぱなしにして、話さない間はマイクをミュートしておく）を
想定している。**発話を検知するまで認識器には何も渡さない**ので、待っている間は
処理が止まっている。ミュート中は CPU 0.0%、メモリは増加せず 17〜21 MB。

ミュートしていれば入力レベルは 0 になる。それが正常な状態なので、`converse` は
これを「ユーザーは黙っているだけ」として扱い、こちらから話しかけない。

## 独立したコンテキストで走る

スキルの frontmatter に `context: fork` を指定しているため、音声のやり取りは
呼び出し元とは別のコンテキストウィンドウで進む。メインの会話に残るのは、
終わりに返す要約と記録のパスだけになる。

往復の書き起こしは過程であって成果物ではなく、とくに黙っている間の応答は
メインに残す価値がない。長時間の待機ではこれが履歴を埋めていくため、分離している。

代わりに、途中で中断すると内容が失われる。そのためスキルには
**区切りがついた時点で記録に追記する**（終わりにまとめて書かない）ことを求めている。

## 読み上げエンジン

読み上げには **AivisSpeech** を使う。Style-Bert-VITS2 ベースで日本語の抑揚が自然、
19 文字の合成が 0.45 秒。話者は [AivisHub](https://hub.aivis-project.com/) から追加できる。

見つからなければ macOS 内蔵音声にフォールバックする（内蔵の日本語音声は compact 品質しか
なく、長く聞くには明瞭さが足りない）。

`/Applications` に置くだけでよく、**アプリを起動しておく必要はない。**
同梱エンジンを必要になった時点で自動起動する。初回はモデル読み込みに 60 秒以上かかり、
以降は起動済みのものを再利用する。

`SynthesisEngine` が話すのは VOICEVOX が定めた互換 API なので、別の対応エンジンを
足すときは `Kind` に 1 ケース（ポートと同梱エンジンのパス）を加えるだけで済む。

AivisHub のモデルを追加するときは、`ACML-NC`（非商用）ライセンスのものを業務利用しない。

### 未導入なら自動で導入する

スキルは開始時に `ensure-engine` を実行する。導入済みならファイルの存在確認だけで
即座に返り、未導入のときだけ GitHub の最新リリースから dmg を落として
`/Applications` に置く。Homebrew の cask が無いため dmg を直接扱っている。

```bash
claude-live/skills/claude-live/scripts/ensure-engine            # 未導入なら導入する
claude-live/skills/claude-live/scripts/ensure-engine --dry-run  # 何を落とすかだけ表示する
claude-live/skills/claude-live/scripts/ensure-voice             # 既定の話者を確かめる
claude-live/skills/claude-live/scripts/ensure-voice --dry-run   # 何を入れるかだけ表示する
```

### 既定の話者も入れる

AivisSpeech に同梱される話者だけでは環境によって声が変わるので、**既定の話者
「にせ」を入れる**（`ACML 1.0`。非商用限定ではないことをマニフェストで確認済み）。

`ensure-voice` は導入済みなら一覧を見るだけで返る。未導入なら配布元の URL を
エンジンの導入 API に渡す。**250 MB のモデルはエンジンに落とさせる**ので、
こちらで抱えたり配布物に含めたりしない。

話者の指定が `config.json` に無ければ、このとき既定として書く。名前から
スタイル ID を引くので、ID を埋め込んではいない。**すでに選んでいれば触らない。**

別のモデルを入れるなら UUID を渡す。`ensure-voice <UUID>`。

CPU アーキテクチャは `uname -m` から判定し、`AivisSpeech-macOS-{arm64|x64}-*.dmg`
を選ぶ。成否は終了コードではなく**実行ファイルの実在**で判定する。
導入に失敗しても音声操作は続けられる（macOS 内蔵音声にフォールバックする）。

検疫属性が付いていた場合は外さずに知らせる。属性を外すのは署名の検証を
回避することになるため、初回だけ Finder から開いて許可してもらう。

### 切り替える

```bash
claude-live/skills/claude-live/scripts/use-engine aivis                   # AivisSpeech の既定話者
claude-live/skills/claude-live/scripts/use-engine aivis 1937616896        # 話者を指定（voices で確認できる）
claude-live/skills/claude-live/scripts/use-engine aivis 1937616896 1.08   # 速度も指定（既定 1.15）
claude-live/skills/claude-live/scripts/use-engine auto                    # 使えるものを自動で選ぶ
```

書き込み先は `~/.config/claude-live/config.json` の 1 ファイルだけなので、戻すのも
同じ 1 コマンド。反映は次のセッションから。

**設定を MCP の登録引数ではなくファイルに置いている。** プラグインで入れた場合の
登録は配布物の `.mcp.json` に固定されていて、そこに話者を書いても利用者ごとの設定に
ならない。ファイルなら、プラグインで入れても手で繋いでも同じ設定が効く。

優先順位はコマンドライン引数 → このファイル → 組み込みの既定値（話者はエンジンが
持つ先頭のスタイル、速度 1.15）。以前の `use-engine` は MCP の登録に `--speaker` を
書いていたため、その登録が残っていると引数が優先されてファイルの設定が効かない。
`use-engine` は残っていれば知らせる。外すのは `claude mcp remove claude-live -s user`。

どの話者で読まれるかは `claude-live voices`（`←` が付く）と `claude-live check` で確認できる。

## 終了時にプロセスを片付ける

放っておくと 2 種類のプロセスが残る。片付け方が違う。

| プロセス | 寿命 | 片付け |
| --- | --- | --- |
| MCP サーバー | セッションと同じ | 標準入力が閉じると 1 秒ほどで自分から終わる |
| 読み上げエンジン | **セッションを越えて残る**（`ppid 1`） | `stop-engines` を `SessionEnd` フックで呼ぶ |

### MCP サーバー

Claude Code が標準入力を閉じた時点で終了する。**ツールの実行中でも待たない。**
`converse` は最大 1 時間ブロックするので、完了を待つ実装だとセッションが終わっても
マイクを掴んだまま残ってしまう。

読み終えた要求への応答だけは書き切ってから終える。

### 読み上げエンジン

エンジンは別プロセスで、起動元から切り離されて残る。次のセッションが起動済みのものを
再利用できる利点があるが、使わない間もメモリを占有する。

**プラグインで入れた場合は `hooks/hooks.json` に同梱してあるので登録は要らない。**
手で繋いでいる場合は `~/.claude/settings.json` に次を書く。

```json
"SessionEnd": [
  { "hooks": [{ "type": "command",
      "command": "<リポジトリ>/claude-live/skills/claude-live/scripts/stop-engines",
      "timeout": 15 }] }
]
```

手で実行してもよい。

```bash
claude-live/skills/claude-live/scripts/stop-engines
```

**止めると次に使うときモデルの読み込みを待つ**（AivisSpeech は 60 秒以上）。
一日中使うなら止めない方が快適で、その場合はフックを外す。

安全のため 2 つの条件で何もしない。

- **他のセッションが MCP サーバーを動かしている** — そちらが使っているため。
  現在のセッションのサーバーが終わるのを最大 5 秒待ってから判定する
- **GUI アプリ（AivisSpeech.app）が起動している** —
  エンジンはアプリが抱えているもので、止めるとアプリが壊れる

## 音声の開始と終了を外へ知らせる

表示や記録など、音声の開始終了に合わせて何かを動かしたいとき用の口が 2 つある。
どちらも**置いていなければ何も起きない**ので、使わない環境では副作用がない。

| 置き場所 | 誰のもの |
| --- | --- |
| `~/.config/claude-live/on-start`（`on-end`） | 利用者が自分で書くもの |
| `~/.config/claude-live/on-start.d/*`（`on-end.d/*`） | 他のプラグインが自分で置くもの |

**`.d` を分けているのは、繋ぎ込みのために利用者のファイルを書き換えたくないため。**
1 つのファイルしか無いと、後から入れたものが既にある内容を壊しかねないし、
消すときにどこまでが自分の分か分からなくなる。ディレクトリなら各自が 1 本置くだけで共存できる。
呼ぶ順はファイル名順で、消し忘れた壊れた symlink は飛ばされる。

加えて `~/.local/state/claude-live/` を作っておくと、いま何をしているかが
`state`（`thinking` / `speaking` / `idle`）に書かれる。

この口と `state` を使う実装が **claude-live-pet**（下記）。

### 終わりをどう検知するか

MCP サーバーはセッションが続く限り生きているので、**サーバーの終了を待っていると
音声を終えても後片付けが始まらない**。そこで `SubagentStop` フックを使う。

スキルは `agent: claude-live:claude-live` で専用のエージェントとして走るため、
`SubagentStop` のペイロードの `agent_type` を見れば、終わったのが音声セッションか
他のサブエージェントかを区別できる。`end-voice-session` がこれを判定して `on-end` を呼ぶ。

**エージェント名はプラグイン名で修飾する。** `agent: claude-live` と書くと解決されず、
黙って `general-purpose` にフォールバックする（実測）。フォールバックしても
スキルは動くが `agent_type` が一致しなくなるため、終わりを検知できない。
プラグインを使わず手で繋いでいる場合もこの名前は解決されないので、
音声の終わりでは片付かず、セッション終了時の片付けだけが効く。

「他のセッションがまだ音声を使っているか」は、`~/.local/state/claude-live/voice/<PID>`
の印で数える。中身はそのサーバーを抱えている Claude Code のセッション ID。
**MCP サーバーの数で判定してはいけない。** サーバーは音声を使わないセッションでも
常駐するので、Claude Code をもう 1 枚開いているだけで永久に「使用中」になる。

印は外から消される前提で扱う。消えたあとに話しかけられれば置き直し、
`on-start` を鳴らし直すので、同じセッションで何度でも始め直せる。

### サーバーの死に方に頼らない

MCP サーバーは標準入力が閉じれば自分で印を外すが、**強制終了させられるとその機会がない。**
実際、印だけが残ってオーバーレイが消えないことがあった（サーバーは終了済みなのに
`~/.local/state/claude-live/voice/<PID>` が残っていた）。

そのため `end-voice-session` は `SessionEnd` からも呼ぶ。こちらは harness が呼ぶので
サーバーの死に方に依存しない。`SessionEnd` のペイロードに `agent_type` は無いが、
セッションごと終わる以上どのサブエージェントだったかは問わなくてよい。

## 画面にドット絵を出す（claude-live-pet）

別のプラグインとして分けてある。入れると、話しているとき・考えているときで動きが変わる
ドット絵が画面の最前面に出る。**claude-live 単体では何も出ないし、入れなくても音声操作は動く。**

```
/plugin install claude-live-pet@claude-live
```

**繋ぎ込みは要らない。** 入れて次のセッションを始めると、`SessionStart` フックの
`connect` が自分で繋ぐ。

```
~/.claude/plugins/data/claude-live-pet-<マーケットプレイス>/current  → いま入っている版
~/.config/claude-live/on-start.d/claude-live-pet                     → current/scripts/start-pet
~/.config/claude-live/on-end.d/claude-live-pet                       → current/scripts/stop-pet
```

`current` を挟むのは、配布物がバージョンごとに別ディレクトリへ入れ替わるため。
これがないと更新のたびに繋ぎ直しが要る。symlink は current 越しなので張り直しも不要。

止めてよいか（他のセッションがまだ音声中でないか）の判断は claude-live 側の `on-end` が
持っている。そこに乗るので、ペット側で二重に実装していない。

外すときはプラグインを消してから、残った symlink を消す。壊れた symlink は
実行可能に見えないため、消し忘れても何も起きない。

### ペットを選ぶ・増やす

スキルが 2 つ付いてくる。**入口のパスを覚えなくてよいので、普段はこちらを使う。**

```
/claude-live-pet:add-pet     ペットを登録する・登録を外す・一覧を見る
/claude-live-pet:select-pet     表示を切り替える・見た目を変える
```

どちらも `disable-model-invocation: true` で、**明示的に呼んだときだけ動く**。
話の流れでモデルが勝手に登録したり切り替えたりすることはない。

中身は次のコマンドで、直接も呼べる（`<入口>` は上の `.../current/scripts`）。

```bash
<入口>/select-pet              # いま選んでいるものと、選べるものを表示する
<入口>/select-pet 9s           # 切り替える（動いたまま 0.2 秒ほどで反映される）

<入口>/add-pet 9s ~/somewhere/9s-frames                      # そのディレクトリを登録する
<入口>/add-pet clawd --sheet ~/Downloads/clawd.webp \
  stand=1 run=6 talk=4 walk=5 think=9                        # シートから切り出して登録する
<入口>/add-pet --forget 9s                                   # 登録を外す（画像は消さない）

<入口>/slice-sheet --inspect ~/Downloads/clawd.webp          # 格子と各行のコマ数を見る
```

**コマ画像は複製せず、置いた場所をそのまま覚える。** 素材は利用者のもので、
どこで管理するかも利用者が決める。複製すると、元を直しても反映されないうえ、
同じものが 2 か所にできる。登録簿（`pets.json`）には名前とパスだけを書く。

移動・削除された登録は一覧で `← 見つからない` と出る。選んだままになっていても、
**起動時は既定のペットに退避して理由を記録する**（自動で起動されるものなので、
何も出ないと理由がその場で分からない）。切り出し（`--sheet`）の出力先は
既定でプラグインの持ち物の下（`pets/<名前>/`）だが、**残したいなら `--out` で
自分の場所を指定する**（既定の場所はアンインストールで消える）。

既定は同梱の `clawd`（Anthropic のキャラクター）。`<動き>=<行番号>` は 1 始まり。
格子は「幅 ÷ 列数」で求め、行数は升目が正方形に近くなるように決める。合わなければ
`--cols` `--rows` で指定する。**コマは升目のまま切り出し、余白を詰めない。**
詰めると、升目の中で位置が変わることで表している上下動が消えてしまう。

ペット 1 匹は次の 3 つでできている。

| ファイル | 中身 |
| --- | --- |
| `*.png` | コマ画像 |
| `manifest.json` | 升目の大きさと、動きごとのコマ一覧 |
| `pet.json` | 沈黙中の出やすさと、動きごとの使うコマ・送りの速さ（任意） |

**ファイル名は自由**だが、コマの順は**ファイル名の並べ替え順**で決まる。10 コマ以上あるときは
0 埋めしないと `frame_10` が `frame_2` より前に来る（`slice-sheet` が 2 桁で書き出すのはこのため）。
`stand` は必須で、無いと起動できない。窓の大きさもこのコマから決まる。

### 見た目を変える

書き込み用の `config.json`（置き場所は `add-pet` の 1 行目に出る）を書き換えると、
次の監視周期（0.2 秒）で反映される。

- `pet` 表示するペットの名前
- `height` 表示する高さ（px）
- `flipped` 左右反転
- `idle` 沈黙中に選ばれる動き。**同じ名前を複数書くと出やすくなる**（重みを並びの回数で表す）
- `sequences` 動きごとに、使うコマ番号と 1 コマの表示時間

`idle` と `sequences` の既定はペット側の `pet.json` にある。**コマの選び方と送りの速さは
素材ごとに違うため**で、`config.json` に書いたものが動きごとに上書きする。
ただし監視しているのは `config.json` だけなので、`pet.json` とコマ画像の差し替えは
起動し直しが要る。**試しながら決めるときは `config.json` 側に書く。**

### 置き場所

| | 場所 | 中身 | 消えるとき |
| --- | --- | --- | --- |
| 配布物 | `<版>/scripts/` | バイナリとスクリプト | 更新で入れ替わる |
| 配布物 | `<版>/resources/pets/` | 同梱のペット | 更新で入れ替わる |
| プラグインの持ち物 | `~/.claude/plugins/data/claude-live-pet-<マーケットプレイス>/` | **登録簿（`pets.json`）**・選んだペット・表示位置・入口（`current`） | アンインストールで消える |
| ペットの実体 | 利用者が決めた任意の場所 | コマ画像 | 利用者が消したときだけ |

`<版>` は `~/.claude/plugins/cache/<マーケットプレイス>/claude-live-pet/<版>/`。

**配布物と書き込みを分けているのは、配布物がバージョンごとに別ディレクトリへ
作り直されるため。** 古い版には `.orphaned_at` が付いていずれ消えるので、
そこへ書くと更新のたびに失われる。プラグインごとの置き場所は更新をまたぐ。

**アンインストールでは、プラグインの持ち物だけが消える。** 登録簿も選択も表示位置も
プラグインの持ち物なので、外せば一緒に消えるのが筋。**消えて困るコマ画像は複製せず
利用者の場所から読んでいる**ので、そちらは残る。登録簿を失っても
`add-pet <名前> <パス>` で戻せる。

## 読み方の辞書

`claude-live/skills/claude-live/resources/dictionary.tsv` に「表層形 / 読み / アクセント型」をタブ区切りで書く。
**リビルドは不要。** 編集内容は `dict preview` では即座に確認でき、
読み上げに反映されるのは次のセッションから（MCP サーバーが起動時に読み込むため）。

```bash
claude-live/skills/claude-live/scripts/claude-live dict preview "PRをrebaseする"   # 読み方を確認（音は鳴らない）
claude-live/skills/claude-live/scripts/claude-live dict install                    # エンジンの辞書に反映
claude-live/skills/claude-live/scripts/claude-live dict list                       # 登録内容を確認
claude-live/skills/claude-live/scripts/claude-live dict clear                      # 全削除
```

### 2 つの経路で処理している

同じファイルを使うが、語の種類によって効かせ方が違う。

| 表層形 | 経路 | 反映に必要なこと |
| --- | --- | --- |
| ラテン文字（`PR`・`async`・`Kubernetes`） | 読み上げ前にテキストをカタカナへ置換 | セッションを開き直す |
| 日本語（`空`・`空文字列`） | エンジンのユーザー辞書 | `dict install` を打つ |

**エンジンのユーザー辞書は、ラテン文字の語には効かない。** 登録しても `PR` はピイアアル、
`async` はアシンク、`rebase` はレバセと読まれる。英語として発音できる語が英語 G2P に
回され、ユーザー辞書を参照しないためと考えられる（エンジンの実装を読んで確認したわけでは
ないので推定）。そのためラテン文字の語は、読み上げる前にこちらでカタカナへ置き換えている。

日本語の語を同じ方式で置き換えないのは、「空」を機械的に「カラ」にすると
「空港」「空間」まで壊れるため。こちらは形態素解析を持つエンジン側の辞書に任せる。

置換は単語境界を見るので、`PR` が `PRODUCT` の一部に当たることはない。
長い語から先に処理するため `HTTPS` が `HTTP` + S に割れることもない。

### 何を登録するか

合成した音声の読みを確かめ、**間違っていた語だけ**を選んでいる。
Style-Bert-VITS2 の英語 G2P は優秀で `Swift` `commit` `deploy` などは辞書なしで正しく読めるため、
むやみに登録するとかえって不自然になる。

編集したら `dict preview` で確認する。狙った語が置き換わっているか、
関係ない語まで巻き込んでいないかが、音を鳴らさずに分かる。

## 使う

音声で操作したいコードベースで起動する。

```bash
claude-live/skills/claude-live/scripts/start-claude-live
claude-live/skills/claude-live/scripts/start-claude-live "認証の設計を相談したい"
```

このスクリプトは「毎ターン必ず思考する」設定だけを外して `/claude-live` を呼ぶ。
モデルと effort は変更しない。速さのために思考を浅くすると応答の質が落ち、
音声で話す意味がなくなるため。

すでに開いているセッションで始めるなら `/claude-live` と打つ。話題も渡せる。

```
/claude-live 認証の設計を相談したい
```

**「音声で話したい」と伝えるだけでは始まらない。** スキルに
`disable-model-invocation: true` を指定しているため、明示的に呼ばないと起動しない。
意図せず音声モードに入って、話しかけてもいないのにマイクを開かれるのを避けるためこうしている。

```bash
claude-live/skills/claude-live/scripts/claude-live check      # マイク権限・認識モデル・読み上げ経路
claude-live/skills/claude-live/scripts/claude-live engines    # エンジンの導入状況
claude-live/skills/claude-live/scripts/claude-live voices     # 話者一覧
claude-live/skills/claude-live/scripts/claude-live bench      # 合成時間を測る
```

```
マイク権限     : 許可済み
ja-JP 対応     : あり
ja-JP 導入状況 : 導入済み
読み上げ経路   : AivisSpeech（話者 1937616896）

```

`設定ファイル` が「未作成」なら話者と速度は既定のまま。`use-engine` で書ける。

ターミナルを許可する。一覧に出てこない場合は `tccutil reset Microphone <bundle-id>`
（例: `com.googlecode.iterm2`）を実行し、ターミナルを Cmd+Q で終了して開き直す。

## 計測済みの値

| 項目 | 実測 |
| --- | --- |
| 日本語認識の処理時間 | 音声 5.34 秒に対し 0.25 秒（実時間の 21 倍速） |
| 認識精度 | 合成音声を入力した 30 文字の文で誤り 1 文字（句読点は自動付与） |
| 合成（19 文字） | 0.45 秒 |
| 読み上げの再生 | 速度 1.1 で 19 文字 2.5 秒 / 44 文字 5.7 秒。速度 1.3 なら 2.1 秒 / 4.8 秒 |

既定の速度は 1.15。`--speed` で変えられる。

15 往復から測った 1 往復の内訳（中央値）:

| 区間 | 時間 |
| --- | --- |
| 読み上げ + 聞き取り | 29.2 秒 |
| 応答の生成 | 16.5 秒 |

話し終えてから声が返るまでの待ちは、無音判定 3 秒 + 生成 16.5 秒 + 合成 0.5 秒。

**読み上げ時間は必要な長さの結果であって、削る対象ではない。** 発話を短く抑えると
内容が足りず答えとして成立しない。生成時間を縮めるために effort やモデルを落とすのも、
質を犠牲にするので採らない。テンポは、無音の間を作らないこと
（考える前に一言返す、重い調査は非同期にする）で保つ。

## トークン消費

15 往復を含むセッションの実測値。

| 項目 | 実測 |
| --- | --- |
| API 呼び出し | 64 回 |
| キャッシュ読み出し | 3,614,091 トークン（1 回あたり 56,470） |
| キャッシュ書き込み | 96,832 トークン |
| 出力 | 31,348 トークン（1 回あたり 489） |
| **キャッシュヒット率** | **97.4%** |

新規入力はわずか 119 トークンで、ほぼ全量がキャッシュから読まれている。
常時コンテキストを占めるのはスキル 5.4 KB とツール定義 1.7 KB だけなので、ここは軽い。

**構造的な弱点は往復数の多さにある。** 音声は短い往復を重ねるので API 呼び出しが増え、
そのたびに会話全体が読み直される。テキストで 1 回に長く答えてもらう場合より総量は増える。

### 沈黙している間はゼロ

ツール呼び出しが待っている間、API リクエストは 1 件も発生しない（9 時間の実測で確認）。

費用が生じるのは**返ってきた瞬間**だけで、しかも安くない。**プロンプトキャッシュの
TTL は 5 分**なので、5 分を超えて待つとキャッシュが失効し、会話全体を
キャッシュ書き込みし直すことになる。書き込みは入力単価の 1.25 倍、読み出しは 0.1 倍で、
**12.5 倍の差**がある。

そのため**聞き直す回数を最小にする**設計にしている。1 回の呼び出しで 1 時間待ち、
発話が無ければそこで終了するので、沈黙のあいだに発生するリクエストは
**終了を判断する 1 件だけ**になる。

待ち時間はツールの引数にしていない。短く刻むとキャッシュ失効の境界を何度も跨ぐため、
呼び出し側から変えられないようにしている。運用側で変えたい場合は環境変数
`CLAUDE_LIVE_RECORDING_LIMIT` / `CLAUDE_LIVE_SILENCE_LIMIT`（いずれも秒）を使う。

費用を抑えるには次の 2 点が効く。

- **新しいセッションで始める**（`claude-live/skills/claude-live/scripts/start-claude-live` はそうしている）。
  キャッシュ読み出しはコンテキストの大きさに比例するので、長い作業の続きで音声を始めると往復ごとに高くつく
- **常駐させるなら `context: fork` が効く**。往復の書き起こしと聞き直しの応答が
  メインの会話に積まれないので、コンテキストが育たない

## 制約

- 読み上げ中の割り込みには未対応。`converse` は読み上げ終了後に聞き取りを始める
- 認識ヒント（`AnalysisContext.contextualStrings`）は未使用。
  技術用語の誤認識はここに用語を登録すれば改善できる
- `SpeechDetector`（OS の発話検出）は `SpeechModule` に準拠しておらず
  `SpeechAnalyzer` に渡せないため使っていない。発話区間は入力レベルで判定している
- Bluetooth ヘッドフォンが出力専用モードのままだとマイクが応答しない。
  その場合は「音声データが 1 件も届かなかった」と明示して終わるので、
  システム設定 → サウンド → 入力 で別のマイクを選ぶ
- **プラグインとして実際にインストールした動作は未検証。** 定義が正しいことは
  `claude plugin validate` で確認済み（プラグイン・配布元とも通る）だが、
  インストールして動かしたわけではない。現在はスキルの symlink と
  `claude mcp add-json` による user スコープ登録で動かしている
- プラグインとして入れると MCP のツール名に名前空間が付く。
  `~/.claude/settings.json` の許可ルールを古い名前のままにしていると、毎回確認を求められる
